# SakuraMeter store publishing setup

The release workflow is triggered by a new `v*` Git tag. It validates the tag against `manifest.json`, builds the extension ZIP once, and reuses that verified artifact for the GitHub Release, Chrome Web Store, and Microsoft Edge Add-ons jobs.

Store publishing is disabled until the matching repository variable is explicitly set to `true`. This lets the workflow be merged safely before credentials exist.

## Prerequisites

- The Chrome Web Store and Edge Add-ons entries must already exist. This workflow updates existing store items; it does not create store listings or edit listing metadata.
- The tag version must exactly match `manifest.json.version`. SakuraMeter currently uses four-part versions such as `3.6.0.62`, so both `v1.2.3` and `v1.2.3.4` tag shapes are accepted.
- Do not create the release tag until the store setup below is complete if you want that release to be submitted to both stores.

## Chrome Web Store

This workflow uses Chrome Web Store API v2 and a Google Cloud service account.

### One-time Chrome setup

1. Open Google Cloud Console and create or select a project.
2. Enable **Chrome Web Store API** for that project.
3. Create a Google Cloud service account. No Google Cloud project role is required just to create it for Chrome Web Store access.
4. Create a JSON key for that service account. Treat the JSON as a password; do not commit it to the repository.
5. Open the Chrome Web Store Developer Dashboard for the publisher that owns SakuraMeter.
6. Under the publisher **Account** section, add the service account email so the service account can manage the publisher's items. Chrome currently allows one service account per publisher.
7. In the Developer Dashboard, open **Publisher > Settings** and copy the **Publisher ID**.
8. Open the SakuraMeter item and copy its **Extension ID**.
9. Ensure the store listing and privacy sections are already complete. The API submission uses the item's existing visibility settings.

### GitHub repository configuration for Chrome

Create these repository **Variables**:

- `CHROME_PUBLISHER_ID` — Chrome Web Store Publisher ID.
- `CHROME_EXTENSION_ID` — SakuraMeter Chrome Web Store extension ID.
- `CHROME_STORE_PUBLISH_ENABLED` — set to `true` only after the two values above and the secret below are configured.

Create this repository **Secret**:

- `CHROME_SERVICE_ACCOUNT_JSON` — the complete service-account JSON key. A minified single-line JSON value is recommended.

When enabled, the job obtains a short-lived OAuth token with the `https://www.googleapis.com/auth/chromewebstore` scope, uploads the verified ZIP through API v2, waits for asynchronous upload processing when necessary, then submits the item using `DEFAULT_PUBLISH`. A successful submission normally enters `PENDING_REVIEW`; the store publishes it after approval according to the existing store settings.

## Microsoft Edge Add-ons

This workflow uses the current Microsoft Edge Add-ons Update REST API v1.1 authentication model: API key plus Client ID.

### One-time Edge setup

1. Sign in to Microsoft Partner Center with the account that owns the existing SakuraMeter Edge extension.
2. Open the **Microsoft Edge** program.
3. Open **Publish API**.
4. If the page offers **enable the new experience**, enable it.
5. Choose **Create API credentials**.
6. Copy the generated **Client ID** and **API key**. Record the API-key expiry date and rotate the key before it expires.
7. Open the SakuraMeter extension in Partner Center. On the Extension overview page, copy the **Product ID** from Extension identity. It is also the GUID shown in the Partner Center URL.

The Edge Update REST API can update an existing product but cannot create a new extension product or update listing metadata. The initial product/listing setup therefore remains a Partner Center task.

### GitHub repository configuration for Edge

Create these repository **Variables**:

- `EDGE_PRODUCT_ID` — SakuraMeter's Partner Center Product ID GUID.
- `EDGE_CLIENT_ID` — the Client ID shown on Partner Center's Publish API page.
- `EDGE_STORE_PUBLISH_ENABLED` — set to `true` only after the values above and the secret below are configured.

Create this repository **Secret**:

- `EDGE_API_KEY` — the API key generated by Partner Center Publish API.

When enabled, the job uploads the same verified ZIP used by the GitHub and Chrome jobs, polls the upload operation until it reports `Succeeded`, submits the draft for certification, and polls the publish operation until it reports `Succeeded`. A failed operation fails the GitHub Actions job rather than being hidden.

## Normal release flow

1. Update `manifest.json.version` and `version_name` to the intended version.
2. Merge the release-ready code to `main`.
3. Create and push the matching tag, for example `v3.6.0.63` or `v3.6.0.63.1`.
4. GitHub Actions validates the version and builds one ZIP.
5. The verified ZIP is reused for:
   - GitHub Release;
   - Chrome Web Store submission, if enabled;
   - Microsoft Edge Add-ons submission, if enabled.
6. Chrome and Edge still perform their own review/certification before the update reaches store users.

## Safety behavior

- A tag/manifest mismatch stops the build before any release or store upload.
- The ZIP's internal `manifest.json.version` is checked again before the artifact is uploaded.
- Missing store credentials do not trigger a store request. If a store is enabled but required configuration is missing, that store job fails with the missing setting name.
- Secrets are passed only through GitHub Actions secret contexts and are not printed.
- API response bodies are not dumped to logs; only safe HTTP/status fields are reported.
- The workflow does not create a test tag, change extension code, edit store metadata, or automatically increment versions.
